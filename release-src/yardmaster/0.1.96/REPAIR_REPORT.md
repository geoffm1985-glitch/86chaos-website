# Yardmaster 0.1.96 direct desktop ChatGPT connection repair

Evidence: the supplied screenshot reports that Yardmaster could not reconnect to its docked ChatGPT window, with Reload then Resume Handoff instructions. The user retried those instructions and the error repeated. The 0.1.95 path retries the same localhost DevTools target discovery and WebSocket transport; reloading the document cannot restore an unavailable transport. The screenshot does not establish whether the PC has a port conflict, target discovery failure, or a WebSocket failure.

Repair: the desktop creates a private parent/child IPC channel for its operator and binds commands directly to its existing ChatGPT WebContentsView through Electron's debugger API. Desktop handoffs bypass target discovery, fixed-port availability and WebSocket attachment entirely. The exact persistent sandboxed dock remains the browser/account in use. Commands, JavaScript results/errors, file chooser events and downloads pass through the private channel. A detached debugger is reattached to that same WebContents; disconnected transports reject pending requests and remove listeners. Startup retries give the dock time to load. Unrecoverable errors include the actual connection detail, preserve the existing failed handoff ZIP, and do not request endless document reloads or enter recursive self-heal. Standalone fallback remains unchanged.

Validation: eight new direct bridge Node regressions, seven existing dock regressions and nine related sign-in/composer regressions passed (24 total). The new tests include an actual Node child-process exchange and the real launch/spawn functions, event forwarding, dock-only download paths, errors, debugger reconnection and cleanup. Two existing dock/feature-contract tests also passed. Syntax and dual coverage inventory passed: 66 features, 37 actions, 19 routes, 19 UI actions, 24 configuration keys, 16 Playwright specs.

Two new Playwright tests launch real Electron with a sandboxed persistent WebContentsView and a local ChatGPT-origin fixture. They exercise the real operator launch and private IPC transport, the signed-in fixture account, retained draft, ZIP file upload and reload/resume reconnection. The tests are parsed and listed successfully; execution remains pending on the user's Windows PC because this environment lacks an Electron runtime. The fixture never signs into or submits work to the live ChatGPT service. No full release gate or iPhone suite was run.

Local command: scripts/Test-Local-Yardmaster.ps1 -ExpectedCommit <delivered SHA> -ExpectedVersion 0.1.96 -ChatGPTDockOnly. It runs only fifteen Node dock/bridge regressions and the two real Electron Playwright tests, with live output, elapsed time, final PASS/FAIL and a current failure ZIP on failure. npm ci installs the Electron runtime; this selection does not require a separate Chromium download.

Installation is required after tests pass: pulling/testing the repo does not update a separately installed desktop. Extract the complete application ZIP and run Install-Yardmaster.cmd, which updates/restarts the installed app. Return to the existing failed run and choose Resume Handoff. The repair reuses the original handoff ZIP and the persistent dock account. Do not create a new run to resume that failure.
