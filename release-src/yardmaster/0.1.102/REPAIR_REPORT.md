# Yardmaster 0.1.102 continuous loop and full-first tests

PC and hosted phone Test Type controls now include **Full first → Failed / Delta**. Choose it and Start Closed Loop to run the full Play Store command once, then failed/delta commands for repair verification and post-deployment checks. The selection remains saved; each new loop starts with full again. A completed first full run switches to delta whether it passes or fails. An interrupted full run remains full until completion. Existing full, delta and targeted selections keep their behavior. History records the actual command type.

The new connected simulation runs the real Yardmaster server against an isolated local repository and bare Git remote. It executes an actual full test process which fails, creates a complete source/evidence handoff ZIP, holds the assistant reply, downloads and applies a versioned repair ZIP, runs delta successfully, commits and pushes, waits for the matching deployment identity, deliberately fails the post-deployment delta, then repeats handoff/reply/apply/delta/push/deployment/delta until PASS. It proves that a matching commit on the wrong branch cannot start post-deployment tests, that the second handoff contains the first repair, that both configured ChatGPT routes are used, and that the full command runs exactly once. A separate passing-first-run check proves no needless handoff or push occurs and a new loop runs full again.

ChatGPT replies and deployment readiness are controlled local boundaries. Test commands, failure evidence, ZIPs, source overlays, commits, pushes, polling and workflow transitions are real. Windows tests use the existing Apply-Repair.ps1 and robocopy; Linux uses a portable overlay only inside the guarded disposable fixture. The test does not contact a live ChatGPT account or Vercel deployment.

Playwright drives the native dashboard and hosted phone controls against that same real local server with a browser-based simulated ChatGPT upload/reply/download page. Hosted controls proxy authenticated requests to the real server. Both flows are included on desktop, Android Chromium and iPhone WebKit. npm run test:continuous:loop includes the new connected tests plus the prior rollover, updater and model-selection regressions; the full Play Store runner automatically includes the new Node and Playwright files.

Validation: syntax and feature coverage passed (76 features); 40 targeted Node checks passed, including the connected two-repair-cycle simulation; three request-only Playwright updater checks passed. All 21 targeted Playwright executions are discoverable. The 18 browser executions remain pending because Playwright browser downloads arrive invalid/truncated in this workspace. Native Windows installation and live signed-in ChatGPT remain pending. The application full release/Play Store gate was not run; the small disposable fixture runs its own real test:play-store command. Production was not changed.
